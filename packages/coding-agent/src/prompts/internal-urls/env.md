- `env://`: live environment of the calling NeoPi session. Root lists names only. Read `env://VISUAL` or `env://EDITOR` for JSON with `state: set|unset` and an effective value. Credential names and password-bearing connection strings are redacted, and normal secret redaction still applies.
- Write `env://NAME` with the exact string, including `""` for an empty value. Write `env://NAME/unset` with content omitted to remove a variable. Writes use the ordinary exec-tier approval policy and are blocked in plan mode.
- Scope and lifetime: inherited environment captured when this session runtime starts, then session-only overrides. Transcript switches in that runtime keep them. No process-global mutation, changes to other sessions, login environment, `.env`, shell startup files or config. Overrides are not persisted. Restarting discards them; resuming a saved transcript cannot restore them.
- Consumers: the TUI's composer, plan, todo and dialog editor launchers resolve VISUAL, then EDITOR, then the platform default on every invocation. Editor children inherit the session environment. New local shell commands observe overrides after shell startup and direnv; ordinary unattended commands still force the non-interactive policy, including EDITOR=true, VISUAL=true and GIT_EDITOR=true. Explicit per-command environments can override ordinary session variables. Existing child processes and eval kernels do not change retroactively. Process-global settings/provider environment readers, discovery caches, managed services, remote ACP terminals and extensions such as `/annotate` that read the process environment directly do not observe session overrides; use their own configuration/restart paths.
- This is a repair interface, not an interactive-launch inheritance fix. Follow the host-environment restoration instructions when starting another interactive TUI from a tool shell.
