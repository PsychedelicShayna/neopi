## D. Important engineering choices made explicitly

1. **Conservative reconciliation, not invented observation coverage.** A newer fetchedAt with no Meter increase does not prove settled usage disappeared. Unconfirmed estimated balances remain visible until eligible positive delta absorbs them or the instance closes. Confirmed allocations plus external match the observed high-water; total key usage additionally includes provisional balances. This intentionally replaces the old contradictory “used is confirmed-only, settlement provisional, next refresh clears selfSince” story. It may overstate allowance consumption; the risk and read model say so. No claim of exact external attribution under simultaneous traffic is made.
2. **Token capacity is explicit operator allocation.** A token Share is not normalized by100. normalize/deny requires declared share_capacity; allow without one remains valid. This is not a provider-size fiction or change to tokens being exact per-key consumption.
3. **Operator bearer instead of an invented Deck identity service.** The inspected Deck route boundary did not supply operator authentication. The correction chooses a complete narrow mechanism: bearer per operator in ephemeral dashboard memory, canonical endpoint role checks and a fixed proxy with no ambient token. Role/actor comes only from the switch; remote credential transport is protected.
4. **Policy revision is not observation revision.** Key edits are strict revision-checked. Moving accounting invalidates a preview only when the selected effect or eligibility changes. This avoids both silent relative rebase and a UI that cannot apply a fixed cap while traffic continues.
5. **One physical-call billing owner.** Generic HTTP, MoA members and asynchronous Job results share the originating Attempt’s Store transaction and one settled consumption latch. requestCounted prevents duplicate request-unit writes during a durable async handoff; there is no separate Job billing flag. Route/MoA callbacks are observers only. Request/output lifetime is separate from a pending job’s retained financial hold.
6. **M1 dependency is closed honestly.** Minimal authenticated read transport ships in M1 because init/status/models require it. Unsupported features are capability-gated; full future handler/jobs/staging functionality is not mandated merely to show one localhost request.
7. **No backend implementation fiction.** The complete proposed spec and ledger settle design contracts; all real implementation and verification remain explicit next gates. The earlier dashboard integration artifact is preserved as evidence and its open host/contract questions are superseded by this proposal, not silently rewritten.
