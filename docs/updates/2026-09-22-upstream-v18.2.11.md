## Integration

- Reseated native xAI transcription in the shared AI transcription dispatcher instead of retaining a second UI-owned provider path. Both `xai/grok-stt` and `xai-oauth/grok-stt` are cataloged as transcription models. The native multipart request keeps `model` before `file`, and OAuth/custom-endpoint transport uses the existing xAI resolver.
- Legacy xAI selection now migrates to the dictation-role chain `xai-oauth/grok-stt,xai/grok-stt`; an explicitly configured dictation role takes precedence. The retired `stt.modelName` UI control and standalone coding-agent xAI adapter are removed.
- Cloud dictation uses disk-backed WAV capture, retains at most five completed recordings per controller, and reports the retained path when transcription fails. Held-capture ownership, final transcript insertion, and local dictation remain on the unified controller.
- Preserved registered eval languages in the session schema after adopting upstream source preparation. Host-side percent-command handling is limited to the built-in Python/JavaScript runtimes, so extension-language source cannot accidentally become a JavaScript package-install request.
- Updated the legacy-extension cache fixtures to the current versioned cache owner while retaining isolation from the database owned by the live upstream installation.
- Regenerated the model catalog from the merged generator and policy sources. Relative to the merged index, the live regeneration adds 95 models, removes the retired `openai-codex/gpt-daybreak-blue-latest` entry, and refreshes 538 existing entries; this is generator output, not a hand-edited catalog or the parked metrics WIP.

## Brand re-seat

- New skill, clip, play, recording-status, registry-recovery, and metaharness guidance uses `APP_NAME`/`PRODUCT_NAME` or static `npi`/`NeoPi` where appropriate. Taskbench and Harbor binary consumers follow the renamed `npi-linux-*` artifacts and `npi` executable.
- The acceptance scan uses actual recursive source-file globs, not directory-only glob arguments. It includes current-product comments as well as displayed text and model-visible instructions.
- Compatibility identities remain intact: configuration/storage paths, environment variables, package IDs, internal URL schemes, serialized fields, authentication/wire headers, worker selectors, hash salts, Harbor's `omp` discriminator, and the real `live.omp.sh`/`skills.omp.sh` endpoints. Historical update records and released changelog entries are not rebranded.
- Warp retains its registered `omp` protocol discriminator. Profile alias files and managed-block markers retain their existing storage identity so rerunning `--alias` replaces an old block rather than appending a duplicate; generated commands and displayed guidance use `npi`.
