Purpose / coverage
This is a source-path-based inventory of likely Spanish-localization surfaces, not a translation. It covers primary interactive terminal UI and command registration paths. It identifies classes of text and representative mechanisms rather than transcribing every literal, since messages are often assembled dynamically, supplied by plugins/providers, or rendered through shared helpers. Treat slash-command names/keywords as protocol identifiers; the owner's decisions require command vocabulary/command-completion translations to be discussed in-loop, and slash commands themselves must remain unchanged.

Text classification guidance
1. Static translatable UI prose: headings, button/action labels, dialog titles, confirmation prompts, warnings, status messages, setting descriptions, command descriptions/argument usage prose, completion descriptions and keyboard hints.
2. Dynamic-but-localized frame: translate surrounding grammar only, preserve interpolated data exactly (model/provider/agent/plugin names, IDs, paths, URLs, counts, key sequences, quoted input, command names). Avoid Spanish inflection that assumes dynamic names have a gender/number.
3. User/provider/extension content: model responses, prompts passed through, plugin/skill/tool descriptions, MCP names/descriptions, persona content, external API errors, file names and command output. Usually preserve as received; decide separately whether a wrapper label is static UI.
4. Protocol / non-user-facing identifiers: slash-command tokens, tool names and IDs, settings IDs, enum values, event/method names, JSON/schema keys, ACP/MCP wire strings, API/provider/model IDs, keybinding IDs, internal URLs and CLI flags. Do not translate; these are consumed or matched by code/integrations. A string appearing in UI is not automatically prose: inspect its rendering/contract.
5. Mixed CLI/terminal output: user-visible in terminal but may be copied into logs, shell commands, prompts or external protocols; classify before translation. Preserve exact shell syntax, paths, flags and examples.

Current owner constraints and glossary review flags
- Keep every slash command token/name unchanged. Never localize `/model`, `/config`, `/roles`, or any other slash token.
- Spanish translations of slash-command descriptions, command completion explanatory text, and vocabulary are proposals for the owner to discuss in-loop, not settled terminology.
- Mark uncertain terms (including product terminology, model/role/agent concepts, command-completion verbs, and labels with overloaded meanings) for review. Do not silently choose a glossary standard from this inventory.
- English command-completion fallback and command renaming are discussion proposals; catalog fallback to English is required.

Prompt/protocol-specific cautions
- Prompt payload is not equivalent to UI copy. Composer text, slash-command invocations, user messages, quoted selections, attached file contents, images/audio/video references and queued prompts are sent to the model or tools. Never translate/rewrite payloads as a side effect of localizing UI chrome. Static prompt explanations/hints may be translatable only when not part of an externally consumed syntax/command contract.
- Command completion combines prose (candidate description, argument hints, empty-state/help text) with exact executable slash tokens, argument syntax and sometimes command names. Translate only separately identified prose; preserve tokens, argument placeholders, quoting, examples that are executable, and completion insertion values.
- ACP request/response labels/options may be rendered by a remote client, not this TUI; ACP method names, schema keys, option values and protocol responses must remain wire-compatible. User-provided question text/labels/descriptions must be passed through, not translated. Localized fallback strings should be distinguishable from caller-supplied content.
- MCP/plugin/extension surfaces mix NeoPi UI wrappers with author-provided copy. Localize built-in labels such as dialog actions/status wrappers, but preserve plugin names/descriptions, tool names, declared parameter names, prompt text, server names and external error/result content unless a separate product rule explicitly says otherwise. A translated wrapper around untrusted copy should not alter/interpret the copy.
- Theme/status-line templates, skill metadata, persona prompts, hooks and extension-provided labels may be runtime-loaded rather than static literals. Inventory of source strings alone cannot guarantee these dynamic surfaces are localized; they need a policy (pass-through vs optional localized metadata) and fallback behavior.
- User-visible errors often include raw exception messages from OS/provider/network/extension boundaries; they may be English or contain identifiers. Do not wrap them in a translation lookup or translate data indiscriminately. Translate a stable local prefix and preserve the error detail.
